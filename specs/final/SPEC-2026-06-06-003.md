# Lights Out の「手」抽象化を env 委譲化 — ハノイ専用前提の漏れによる accuracy≈0 / L2 データ破損の修正

## 1. 目的・動機

Lights Out スイープ（`results/lights_out/deepseek-r1-distill-qwen-7b/`）で **全試行 accuracy=0** を確認。
調査の結果、env・採点ロジック（`LightsOutEnv.solve()` / `goal_reached()` / `evaluate_state()`）は正常で、
**ランナー側にハノイ専用の「手 (move)」前提が 3 箇所漏れている**ことが原因と判明した。

観測事実（`results/lights_out/.../N3_T0_3/summary.json` ほか全セル）:
- 全試行 `early_stop: "no_move_catchall"`
- 全試行 `reasoning_tokens: 0`
- 全 npz が `move_texts: ['__fallback__']`
- `total_tokens` は約 1000〜1400 に集中

### 根本原因（影響度順）

**① 【主因】early-stop の手数カウントがハノイ専用 `_MOVE_RE`（`runners/run.py:181`）**
- `_MOVE_RE = r'Move\s+\d+\s+from\s+([ABC])\s+to\s+([ABC])'` は Lights Out の手 `Toggle (r,c)` に一切マッチしない。
- Algorithm D `_check_no_move`（`runners/run.py:200`）は
  `len(text)/3.5 > num_predict * no_move_ratio(=0.25)` かつ「手 0 本」で `no_move_catchall` を返す。
  Lights Out では手数が常に 0 と誤認されるため、`num_predict=4096 × 0.25 ≈ 1024` トークン到達で**毎回強制停止**。
- 結果、モデルは `<think>` 推論の途中（答えの Toggle 列を出力する前）で切られ、解答に到達できない。
- データと整合：`total_tokens ≈ 1000〜1400`、全試行 `no_move_catchall`。

**② 【症状】`reasoning_tokens: 0`**
- ① により `</think>` 到達前に切られ、`<think>...</think>` 正規表現がマッチしない。①の従属症状。

**③ 【プロンプト汚染】`SYSTEM_HINT` がハノイ固定（`runners/run_local.py:87`）**
- system メッセージが "You are an expert at the **Tower of Hanoi** puzzle. Always apply the recursive strategy..."。
  `--n-shot 0` でも必ず注入され（`runners/run_local.py:236`）、Lights Out の思考をミスリードする。

**④ 【L2 研究データ破損】隠れ状態キャプチャもハノイ専用 `_MOVE_RE_WITH_DISK`（`runners/run_local.py:42, 505`）**
- `Toggle` を拾えず Move 完了ステップを検出できないため、全 npz が `__fallback__`。
- 本研究の本命である **L2 隠れ状態（layer_top/mid/low）が Lights Out では全滅**。
  accuracy には効かないが、Move 位置での隠れ状態という解析対象が取得できていない。

### 本 SPEC のゴール
ランナー（`run.py` / `run_local.py`）から「手」のパズル依存ロジックを排除し、
**`BaseEnv` に委譲する**ことで、Lights Out を含む任意パズルで
(a) early-stop が正しく機能、(b) パズル適合の system hint、(c) Move 位置の隠れ状態キャプチャ
が成立する状態にする。修正後、Lights Out スイープは**全面再実行が必要**（既存データは破棄）。

### 決定事項（GATE A 壁打ち / 2026-06-06）

| # | 論点 | 決定 |

## 2. 物理的要件【physics-agent 担当】

### 2.1 保存則・対称性の要件
- 本 SPEC は**測定の正しさ（measurement correctness）の修正**であり、ポテンシャル・ハミルトニアン・外力の定義は変更しない。
- 「Move 位置で隠れ状態をサンプリングする」測定プロトコルは秩序変数の定義に直結する。
  Lights Out の「手」= `Toggle (r,c)` は **GF(2) involution・可換・無順序集合**（対称性は $\mathbb{Z}_2^{N^2}$）であり、
  ハノイの (src,dst)（$S_3$ ペグ置換 gauge、順序付き非可換）とは群構造が根本的に異なる。
- **【caveat A／physics 指摘】** この可換性により、Toggle 位置サンプルは**静的**秩序変数
  （basin 分離 P(q)、self-overlap q_EA）には有効だが、Move 軸が**順序 gauge** になるため、
  H3 系の**動的・循環解析（非勾配循環 / NESS 確率カレント $J_{ss}$、per-move 方向 overlap）はそのまま移植不可**。
  循環署名は decode 順アーティファクトと交絡する。可換系の動的秩序変数は順序 gauge の商空間で再定義が必要（将来 SPEC への申し送り）。

### 2.2 極限値チェック項目
- early-stop 無効（`--no-early-stop`）時に Lights Out で accuracy>0 が観測できること（① が主因であることの確認）。
- ハノイの挙動が本修正で**不変**であること（回帰なし）。

### 2.3 スピングラス・Hopfield・RSB との整合性
- L2 隠れ状態が正しい Move 位置で取得されることは、P(q) / q_EA 解析の前提。
  `__fallback__`（最終トークン1点のみ）では q_EA が定義不能（Move 位置 2 点未満）、P(q) は basin でなく打ち切り点を測る。本修正はこの前提を回復する。
- **【caveat A 続き／要実測】** Lights Out は `<think>` 内で線形系を解いてから**解集合を末尾で一気に出力**する構造になりやすく
  （プロンプトが "Output ONLY the moves"）、連続 Toggle の隠れ状態が answer-dump 中の近接トークンで自明に高相関化し q_EA を人工的に押し上げる懸念。
  → 再 sweep 後の最初の解析で、連続 Toggle 隠れ状態の自己相関をハノイ Move 自己相関と比較し、answer-dump 縮退の有無を実測してから q_EA を解釈すること。

### 2.4 懸念点・要確認（物理）
- **Move 位置の定義**：各 `Toggle` 出力直後の隠れ状態で良い（ハノイの Move 完了点と測定論的に等価）。
  ただし末尾一括出力で Move 位置が 0〜1 個に潰れないか、検証セルで **1 trial あたりの Toggle 数分布**を確認すること。
- **【caveat B】既存 Lights Out データの破棄は「妥当」ではなく物理的に必須**。
  accuracy はバイアスされた打ち切り測定、L2 `__fallback__` は basin でなく打ち切り点（no_move 発火位置≈1024 トークン）を測る systematic bias。
  保持すると後続 P(q)/q_EA/臨界減速に汚染が伝播する。
- **【caveat C／事実訂正済み 2026-06-06】h は既に揃っている（control 不要）**：
  physics-agent は CLAUDE.md の「ハノイは n_shot=2」記述に基づき「ハノイ $h=2$ vs Lights Out $h=0$」の交絡を指摘したが、
  **実データを確認した結果これは誤前提**。ハノイの本番スイープスクリプトは3本とも `N_SHOT=0` がデフォルト
  （`runners/scripts/run_full_sweep.sh:49` / `run_collapse_phase_sweep.sh:41` / `run_full_sweep_v2.sh:40`、echo にも `(h=0)` を明記）。
  → **ハノイ本番データも $h=0$**。決定事項 #5（Lights Out $h=0$）と一致し、cross-puzzle 比較に **h-交絡は無い**（両者 $h=0$ の同一外場点）。
  したがって de Almeida–Thouless 線に沿う外場差の問題は本データには発生せず、**control は不要**。
  - 留意（インフラ）：`meta.json` は現状 `n_shot` を記録しないため、上記は**スクリプト既定値からの推定**（標準起動 `bash run_full_sweep.sh --analyze` を前提）。
    将来の追跡性のため `run_local.py` が `meta.json` に `n_shot` を記録するのが望ましい（本 SPEC スコープ外の小改善）。
  - 要追認（user）：CLAUDE.md「物理変数表／few-shot」節の「ハノイ n_shot=2」は実態（=0）と不一致。CLAUDE.md 側の記述修正が必要。
  - 静的 P(q)/q_EA の cross-puzzle 比較は h 一致のもとで有効（ただし caveat A：可換系の**動的**循環解析は別途移植不可、は引き続き有効）。

## 3. 関連文献【research-agent 担当】

### 3.1 直接関連する先行研究（Lights Out の GF(2) 求解 — 実装の正しさの裏付け）

| 著者 / タイトル / 年 | 出典 | 重要度 |
|---|---|---|
| Anderson, M. & Feil, T. "Turning Lights Out with Linear Algebra" (1998) | Mathematics Magazine 71(4), 300-303. DOI:10.1080/0025570X.1998.11996658 | 高 |
| Sutner, K. "Linear cellular automata and the Garden-of-Eden" (1989) | The Mathematical Intelligencer 11, 49-53. DOI:10.1007/BF03023823 | 中 |

- Anderson-Feil：Lights Out を GF(2) 線形系 `A x = b`（A = adjacency + I）として定式化。可解条件・解個数を核次元で与える。env 採点（`LightsOutEnv.solve()`/`goal_reached()`）の正しさの標準参照。
- Sutner：σ-game / involution・可換・線形の枠組み。Section 2.1 の「Toggle は GF(2) involution でハノイの (src,dst) と代数構造が異なる」の根拠。
- **解の一意性**：3×3 は A が GF(2) 可逆（核次元 0）で**任意の可解配置に一意解**＝パズル必須制約「解は一意」を N=3 で満たす。**5×5 は核次元 2 で 4 解となり一意でない**（将来 N 拡張時の要注意点）。

### 3.2 novelty 観点での位置づけ

| 著者 / タイトル / 年 | 出典 | 重要度 |
|---|---|---|
| Shojaee, P. et al. "The Illusion of Thinking" (Apple, 2025)（既知） | https://machinelearning.apple.com/research/illusion-of-thinking | 高 |
| Zhang, X. et al. "Logical Phase Transitions: Understanding Collapse in LLM Logical Reasoning" (2026, ACL2026) | arXiv:2601.02902 | 高 |
| Lawsen, A. (C. Opus) "The Illusion of the Illusion of Thinking" (2025) | arXiv:2506.09250 | 中 |

- マルチパズル横断の崩壊則を扱う最近接先行は Apple 論文（複数パズルで複雑度に対する崩壊を横断観測）と Zhang et al.（崩壊を「臨界論理深度を超えた相転移」として明示フレーミング）。本研究のハノイ＋Lights Out＋N-puzzle＋Frog Jump 横展開はこの流れに位置づく。
- **novelty 余地（見当たらない＝余地あり）**：いずれも *精度ベースの現象論* に留まり、(i) スピングラス/RSB ハミルトニアン構築、(ii) L2 隠れ状態の P(q)/q_EA 相分類、(iii) ポテンシャル上の制御モデル介入、には踏み込んでいない。本研究の核は先行と重複しない。
- Lawsen の反証（崩壊は出力トークン上限による測定アーティファクト）は、本 SPEC が修正する「early-stop 切り詰めによる accuracy=0」と問題構造が同型。測定の正しさを担保してから崩壊を論じる本 SPEC の方針を外部から支持。

### 3.3 few-shot＝外部磁場 h の対応（CLAUDE.md 物理変数表）

- 「few-shot 例示数を外部磁場 h とみなす」対応を *そのまま* 磁場と呼ぶ統計力学文献は**見当たらない**（プロジェクト独自のアナロジー）。経験的裏付け（例示が精度を安定化・順序依存）は Brown et al.「Language Models are Few-Shot Learners」(2020, arXiv:2005.14165) / Lu et al.「Fantastically Ordered Prompts」(2021, arXiv:2104.08786) で確立。ただし ICL を相転移として扱う流れ（例: arXiv:2604.12151）でも制御パラメータは**タスク多様性 K であり shot 数ではない**。
- → 「shot 数 = h」は本研究独自。主張時は経験的観察にのみ依拠し、磁場対応は**作業仮説**として明示するのが安全。決定事項 #5・caveat C と整合。

## 4. アルゴリズム仕様【implementation-agent 担当】

### 4.1 設計方針（OOP：パズル依存ロジックを env へ委譲）

「手の抽出・カウント・ループ判定・system hint」をパズル横断のインターフェースとして `BaseEnv` に集約し、
ランナーはモジュールレベルのハノイ正規表現（`_MOVE_RE` / `_MOVE_RE_WITH_DISK`）に依存しないようにする。

`BaseEnv` に以下を追加（メソッド名は実装側の裁量、役割を固定）:
1. `count_moves(text) -> int` … early-stop 用の手数カウント。既定実装は `len(self.extract_moves_from_text(text))`。
2. `get_system_hint() -> str` … パズル固有の system メッセージ。Hanoi は現行 `SYSTEM_HINT` 相当。
   Lights Out は GF(2)戦略ヒント（決定事項 #1）。具体文の例：
   "You are an expert at Lights Out. Each cell needs to be toggled at most once; the order does not matter. Determine the set of cells to toggle that turns all lights off (this is a GF(2) linear system)."
3. `extract_moves_with_position(text) -> list[(move_str, char_index)]` …
   隠れ状態キャプチャ用。「新しい手が出現した step」を検出するために、手の文字列と出現位置を返す。
   既定実装は `extract_moves_from_text` を流用して位置を付与。
4. ループ判定キー（Algorithm C 用）は env 依存だが、Lights Out は involution で C を無効化済み（`--no-loop-detection`）。
   ハノイの (src,dst) ループ判定は現状維持でよい（C を env 委譲するかは 4.3 の選択肢参照）。

### 4.2 既存コードとの接続点（ファイルパス:行）

- `envs/base_env.py` … 上記 1〜3 のインターフェース（抽象/既定実装）を追加。
- `envs/hanoi_env.py` … `count_moves` / `get_system_hint`（再帰戦略）/ `extract_moves_with_position` を実装（現行挙動を維持）。
- `envs/lights_out_env.py` … 同 3 メソッドを実装。`extract_moves_from_text`（`Toggle` 抽出）は既存（`lights_out_env.py:92`）を流用。
- `runners/run.py:181` `_MOVE_RE` を使う `_check_no_move`（:200）/ `_check_move_ceiling`（:210）/ `_check_move_loop`（:217）/ `check_early_stop`（:235）:
  `text` から手数を数える箇所を **env 委譲（`count_moves` / env の手リスト）** に置換。
  → `check_early_stop` に env もしくは「手リスト/手数」を渡すシグネチャ変更が必要。後方互換のためデフォルト引数で段階導入。

  `build_few_shot_messages`（:115）と `_prepare_input_ids` の n_shot=0 分岐（:236）の system content を `env.get_system_hint()` に置換。
- `runners/run_local.py:505` `_MOVE_RE_WITH_DISK.findall` による Move 検出 →
