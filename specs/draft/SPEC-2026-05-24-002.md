# run_local.py の env 非依存化（パズル横断実験の実行基盤）

## 1. 目的・動機

現在 `runners/run_local.py` は `TowerOfHanoiEnv` を直接生成しており、Lights Out 等の新規パズルで
実験を走らせるには `run_local.py` の大幅な書き換えが必要になる。

本 SPEC では `run_local.py` の実験ロジックを `env: BaseEnv` を受け取る形に変更し、
**パズルを切り替えるだけで同じランナーが動く設計**にする。

**前提**：SPEC-2026-05-24-001 が実装済みであること（`BaseEnv`, `TowerOfHanoiEnv`, `LightsOutEnv` が確立済み）。

**不変の制約**：
- 早期終了ロジック（`run.py` の `EarlyStopConfig`, `check_early_stop`）は**変更しない**
- 隠れ状態キャプチャ（`make_capture_layers`, npz 書き出し）は**変更しない**
- 既存の `run_full_sweep.sh` でハノイ実験が変わらず動くこと

---

## 2. 物理的要件【physics-agent レビュー案】

本 SPEC は純粋なインフラリファクタリングであり、物理的な計算ロジックを変更しない。

確認事項（軽微）：

- `check_early_stop` は `accumulated_text` のパターンマッチングで動作し、env に依存しない  
  → Lights Out 実験でも同じ早期終了判定が走ることの物理的含意を理解したうえで使用する  
  （`move_loop_repeat` / `move_loop_reverse` は "Move X from Y to Z" パターンが前提。  
   Lights Out の "Toggle (i,j)" には適用されないため、**Lights Out では Algorithm C が機能しない**）

**physics-agent 確認事項**：
- [ ] Lights Out で `check_early_stop` の Algorithm C（ループ検出）が機能しないことの物理的影響  
  （SG 相のループシグナルが取れなくなる → P(q) 解析に影響するか？）

### 4.2 出力パスの確認

既存の sweep スクリプト（`run_full_sweep.sh`）は `--model-id` から slug を生成して出力先を決定する。
パズル種は slug には含まれないため、以下の拡張を検討する（将来対応として SPEC-B には含めない）：

```
results/hanoi/full_sweep/<model-slug>/N{N}_T{T}/  ← 既存（ハノイ）
results/lights_out/full_sweep/<model-slug>/N{N}_T{T}/  ← 将来
```

**現状の範囲**：SPEC-B は `run_local.py` の内部変更のみ。sweep スクリプトの変更は別 SPEC。

### 4.3 後方互換性の確認

既存のハノイ実験（`python run_local.py --N 3 --trials 5`）は `--puzzle` 省略時に `hanoi` がデフォルトになるため、**コマンド変更なしで動作継続**することを確認する。
