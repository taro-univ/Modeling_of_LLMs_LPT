# Algorithm C（ループ検出）の OOP 化 — env 委譲によるパズル横断のループ意味論

## 1. 目的・動機

Algorithm C（`runners/run.py:217` `_check_move_loop`）はハノイ専用の「手」表現
`(src, dst)`（`_MOVE_RE` 由来）に固定されており、ループ意味論が env から切り離されていない。
SPEC-2026-06-06-003 では C をスコープ外（最小修正＝D/B のみ env 委譲）とし、Lights Out では `--no-loop-detection` で無効化して回避した。
本 SPEC はその積み残しを解消し、**「何をループとみなすか」をパズル（`BaseEnv`）に委譲**して OOP 化する。

### なぜ重要か（物理的位置づけ）

`move_loop_repeat` / `move_loop_reverse` は CLAUDE.md の相対応表で **スピングラス相 (SG)** にマップされる早期終了ラベルであり、
ループ検出は単なる打ち切り機構ではなく**相分類の入力**である（H3：非勾配循環＝NESS の振る舞いに関わる）。
したがってループ意味論がパズルの代数構造に整合していないと、SG 相判定にアーティファクトが混入する。

### 現行 C の2規則（ハノイ）

- **C-1（repeat）**：直近 `loop_window` 手の中で同一手が `loop_min_count` 回以上 → `move_loop_repeat`。
- **C-2（reverse）**：A→B の直後に B→A → `move_loop_reverse`。

### パズル代数構造とループ意味論の不整合（physics 指摘 SPEC-003 caveat A）

- **ハノイ**：手は順序付き非可換（$S_3$ ペグ置換 gauge）。A→B→A は実際に盤面を往復させる物理的ループ → C-2 は妥当。
- **Lights Out**：手は **GF(2) involution・可換・無順序集合**（$\mathbb{Z}_2^{N^2}$）。
  - 同一 Toggle を2回 = 恒等（自己キャンセル）。これは「往復」ではなく**冗長手**であり、最適解には現れない。
  - 出力順は自由 gauge のため、**C-2（reverse）型のループ署名は decode 順アーティファクト**であり、SG 的循環とは区別できない（caveat A と同根）。
  - → Lights Out で C-2 をそのまま適用すると SG 相を誤検出する危険。

### 本 SPEC のゴール

`BaseEnv` に「ループ判定」を委譲するインターフェースを設け、各パズルが自身の代数構造に整合したループ意味論を実装できるようにする。
ハノイは現行 C-1/C-2 の挙動を**完全維持**（回帰ゼロ）。Lights Out は可換性に整合した意味論（下記 4.1 の選択肢、要 user/physics 判断）を実装する。

## 2. 物理的要件【physics-agent 担当】

### 2.1 保存則・対称性の要件
- ループ意味論はパズルの対称群に整合すること。可換系（Lights Out, $\mathbb{Z}_2^{N^2}$）では順序 gauge で不変な量のみをループ署名に使う。
- 非可換系（ハノイ, $S_3$ gauge）では現行の (src,dst) 往復が物理的ループとして妥当。

### 2.2 極限値チェック項目
- ハノイ：本 OOP 化の前後で C-1/C-2 の発火が**完全一致**（`tests/test_early_stop.py` 全 PASS）。
- Lights Out：最適解手列（`env.solve()`）に対して C が**誤爆しないこと**。

### 2.3 スピングラス・Hopfield・RSB との整合性
- `move_loop_*` は SG 相の入力。可換系で order-gauge アーティファクトを SG と誤分類しないことが、H3（非勾配循環 / $J_{ss}$）の正しい判定に必須。
- 可換系の「動的循環」は順序 gauge の商空間で再定義が必要（SPEC-003 caveat A の申し送り）。本 SPEC で Lights Out の C をどう定義するかはこの論点に直結。

### 2.4 懸念点・要確認（物理）
- **【physics 確定】C を Lights Out で相/レジーム分類の入力にしない（censoring 機構に降格）**。
  C-1 発火は記号出力レベルの degenerate repetition（stall）であり、H3 が問う L2 hidden-state の非勾配循環（$J_{ss}\neq0$）とは別物。
  レジーム/相の帰属は L2 hidden-state P(q)/$q_{EA}$ パイプラインに一本化する。`early_stop` ラベルは「停止理由の記録」としてのみ保持。
- **【代数的補強】可換 involution（$T^{-1}=T$）により、ハノイの C-2（往復 A→B→A）は Lights Out では「同一トグルの2回出力」に縮退する。
  すなわち C-1 が C-2 を吸収**しており、`is_reverse_pair`→常に False は二重カウント回避として**物理的に必須**（設計裁量ではない）。
- **【user 判断確定 2026-06-06】** (1) **YES：C ラベル降格をハノイの move_loop にも波及**させる。
  ただし **Oscillatory（リミットサイクル/非勾配循環）レジームは PM に統合せず、独立レジームとして維持**する。
  変えるのは判定根拠のみ：early_stop ラベル `move_loop` 単独では Oscillatory に帰属させず、**L2 隠れ状態の $J_{ss}\neq0$ 実測で確定**する（ラベルは暫定的手がかり＋停止理由の記録）。H3 の「$J_{ss}$ 実測で確定予定」と整合。
  (2) CLAUDE.md early_stop 表の「move_loop→SG 相」記述は **更新済み**（4-regime / move_loop→Oscillatory（手がかり）/ 相帰属は L2 に一本化）。

## 4. アルゴリズム仕様【implementation-agent 担当】

### 4.1 設計方針（ループ判定の env 委譲）

`BaseEnv` に「ループ署名」を抽出するインターフェースを追加し、`_check_move_loop` を署名ベースに一般化する。

提案インターフェース（メソッド名は実装裁量、役割を固定）:
- `loop_signature(move_str) -> Hashable` … C-1（repeat）用の正規化キー。
  ハノイは `(src, dst)`、Lights Out は `(r, c)`（Toggle セル）。
- `is_reverse_pair(move_a, move_b) -> bool` … C-2（reverse）用の往復判定。
  ハノイは `src1==dst2 and dst1==src2`。**Lights Out は下記 #L の方針に従う**。

`runners/run.py` 側：
- `_check_move_loop`（:217）を、モジュールレベルの (src,dst) 直書きから `env.loop_signature` / `env.is_reverse_pair` 経由に置換。
- `check_early_stop`（:235）が env もしくは手リストを受け取れるよう、SPEC-003 と同じ env 委譲シグネチャに乗せる（003 実装後を前提とし、本 SPEC は 003 の後に着手）。

**#L Lights Out の C 意味論 → 【決定 2026-06-06：(L-b) を採用】**
- (L-a) C 無効を env で明示。
- **(L-b)【採用】C-1 のみ（冗長手検出）**：同一 Toggle の反復のみ `move_loop_repeat` として検出（恒等手の無限反復＝停滞の検知）。
  **C-2（reverse）は可換 gauge アーティファクトなので無効化**（`is_reverse_pair`→常に False）。
  → `loop_signature` = `(r, c)`、`is_reverse_pair` = 常に False を Lights Out で実装する。
- (L-c) 商空間で再定義（実装コスト最大・非採用）。

### 4.2 既存コードとの接続点（ファイルパス:行）
- `envs/base_env.py` … `loop_signature` / `is_reverse_pair` の抽象/既定実装を追加。
- `envs/hanoi_env.py` … 現行 (src,dst) 挙動を実装（回帰維持）。
- `envs/lights_out_env.py` … #L の採用案を実装。
- `runners/run.py:217` `_check_move_loop` … env 委譲に置換。`run.py:181` `_MOVE_RE` への C 依存を解消。
- 依存：**SPEC-2026-06-06-003（D/B の env 委譲 + check_early_stop シグネチャ変更）の実装完了後に着手**。

### 4.3 設計上の制約・注意事項
- ハノイ回帰ゼロ必須（`tests/test_early_stop.py::TestAlgorithmC` 等 全 PASS）。
- `tests/test_lights_out_env.py` に (L-b) のユニットテスト追加：
  (i) `env.solve()` 最適解で C-1 非発火、(ii) 同一トグル反復で `move_loop_repeat` 発火、(iii) `is_reverse_pair` 常に False、
  (iv) **冗長手を含むが goal 到達する非最適列を C-1 が goal_reached より先に潰さないこと**（`loop_min_count` を偶発的単発冗長で発火しない値に設定）。
