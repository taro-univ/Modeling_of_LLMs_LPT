# stagnation_after_move 相帰属診断スクリプト

## 1. 目的・動機

現行の相分類アルゴリズムにおいて `stagnation_after_move`（手を ≥1 個出した後に停止）の
物理的相帰属が未定。`hypotheses.md` の PM 定義には含まれているが、SG 的解釈も成立しうる。

このスクリプトは以下を **実証的に確認する診断ツール**である：

- `stagnation_after_move` 試行の P(q) 分布が `move_loop` 試行（SG シグナル）に近いか
- `stagnation_after_move` 試行の P(q) 分布が `no_move_catchall` 試行（PM シグナル）に近いか

この結果により **Q3（stagnation の相帰属）を決定**し、後続の P(q) ベース相分類再設計に進む。

対応する未解決問題：
- `open_questions.md` U2（SG 相の判定基準）
- `research_state/hypotheses.md` H3（move loop ↔ 局所安定状態）

## 2. 物理的要件【physics-agent 審査済み — 2026-05-21 全体レビューより】

### 2.1 測定量の定義

各試行の時間平均 hidden state：

$$
\bar{h}^{(\alpha)} = \frac{1}{T_\alpha} \sum_{t=1}^{T_\alpha} h_t^{(\alpha)}
$$

試行間コサイン類似度（P(q) の素材）：

$$
q^{\alpha\beta} = \cos\!\left(\bar{h}^{(\alpha)},\, \bar{h}^{(\beta)}\right)
= \frac{\bar{h}^{(\alpha)} \cdot \bar{h}^{(\beta)}}{\|\bar{h}^{(\alpha)}\| \cdot \|\bar{h}^{(\beta)}\|}
$$

early_stop type 別に**同タイプ内**の全ペア $q^{\alpha\beta}$ を集めて分布化する。

### 2.2 グループ定義

| グループ名 | early_stop ラベル | 想定される相 |
|---|---|---|
| `move_loop` | `move_loop_repeat`, `move_loop_reverse` | SG（基準） |
| `stagnation` | `stagnation_after_move` | **未定（本スクリプトが答えを出す）** |
| `no_move` | `no_move_catchall`, `move_ceiling` | PM（基準） |
| `ordered` | `goal_reached` | Ordered（参照） |
| `think_budget` | `think_budget` | （参照のみ、相分類から除外候補） |

### 2.3 判定基準（物理的解釈）

| 観察結果 | 解釈 |
|---|---|
| stagnation P(q) ≈ move_loop P(q) | stagnation は **SG 的**（局所安定状態に捕捉） |
| stagnation P(q) ≈ no_move P(q) | stagnation は **PM 的**（熱揺らぎで coherence 消失） |
| stagnation P(q) が両者の中間または形状が異なる | **独立カテゴリ（境界シグナル）** 候補 |

判定は**絶対値ではなく分布形状と相対差**で行う（等方化なしのため絶対値 0.7–0.9 付近に集中する問題を考慮）。

### 2.7 Q3 最終判定【user 確定 — 2026-05-22】

**`stagnation_after_move` = PM 寄りの補助シグナル**

根拠（Round 3 分析、`specs/log/SPEC-2026-05-21-001/round3.md`）：

1. 出現頻度が極めて低い（10/450 = 2.2%）→ 主要終了機構ではない
2. stagnation 発生セルの 62.5% が PM 優勢域（SG/(SG+PM) < 0.35）
3. 発生時の物理状態：少数の手で v_score≈1.0 のまま停止 → PM の coherence 消失に近い
4. SG 的ループ（同一状態の循環）とは異なる挙動

Round 2 の暫定判断（SG 寄り）は n=1 pair での観測であり、統計的に不十分と判断。
Round 3 の文脈分析を優先する。

**後続 SPEC への引き継ぎ**：`stagnation_after_move_rate` は SPEC-2026-05-22-001 の
P(q) 相分類器において PM 補助シグナルとして実装済み（整合）。主判定には使わない。

### 2.4 物理的制約

- 比較は**同一 (N, T) 条件内**で行う（同じ quenched disorder、同じ温度）
- レプリカ定義（Q1 確定）：同一プロンプト・同一 N・同一 T・異なる乱数シードの試行
- n_trials ≥ 2 のグループのみ対象（ペアが作れない場合はスキップ）
- 3 層すべて（`layer_top` / `layer_mid` / `layer_low`）を比較し、層依存性を確認する

### 2.5 注意事項

- 等方化なし（raw hidden state）。絶対値は高いが、グループ間の差異が診断の主眼
- stagnation 試行は温度によっては出現頻度が低い → 統計に注意（n_trials を図中に明示）
- この結果は Q3 の判断材料であり、最終的な相分類アルゴリズムではない

## 4. アルゴリズム仕様【implementation-agent 担当】

### 4.1 擬似コード

```
入力: sweep_dir, layer (default: layer_top), ns, ts
出力: P(q) 比較図 × (N, T) + 統計テーブル + aggregate 図

for each (N, T) in (ns × ts):
    cond = load_condition(sweep_dir, N, T, layer)
    if cond is None: skip

    # 試行の時間平均 hidden state を計算
    h_bars = {trial_idx: mean(H, axis=0) for trial_idx, H in enumerate(cond["hidden"])}

    # early_stop type でグループ化
    groups = {
        "ordered":    [idx for idx, label in early_stops if label == "goal_reached"],
        "move_loop":  [idx for idx, label in early_stops if label in LOOP_LABELS],
        "stagnation": [idx for idx, label in early_stops if label == "stagnation_after_move"],
        "no_move":    [idx for idx, label in early_stops if label in NO_MOVE_LABELS],
        "think_budget": [idx for idx, label in early_stops if label == "think_budget"],
    }

    # グループ内全ペアのコサイン類似度
    pq_by_group = {}
    for group_name, trial_indices in groups.items():
        if len(trial_indices) < 2: continue
        pq_by_group[group_name] = [
            cosine(h_bars[i], h_bars[j])
            for i, j in combinations(trial_indices, 2)
        ]

    # 可視化（overlaid histogram + KDE）
    plot_pq_comparison(pq_by_group, N, T)
    save → figures/stagnation_diagnostic/<slug>/<layer>/N{N}_T{T}.png

    # 統計テーブル（mean, std, median, n_pairs per group）
    print_stats_row(pq_by_group, N, T)

# aggregate: 各グループの mean(q) を T の関数としてプロット（N ごとに）
plot_mean_q_vs_T(all_results)
save → figures/stagnation_diagnostic/<slug>/<layer>/aggregate_N{N}.png
```

### 4.5 implementation-agent 設計確認

- **確認日**: 2026-05-21
- **コメント**:

  **仕様書とコードの整合確認**

  1. **`load_condition` の引数形式**:
     `analyze_integrated.py` の `load_condition(dirs: list[Path], N, T, layer)` は複数ディレクトリを受け取る設計。
     CLI では `--dir` を `nargs="+"` にして複数指定可能にし、全 dirs をリストとして渡す。
     （仕様書の `--dir2` は `--dir` の2番目引数で代替可能）

  2. **`is_fallback` のスキップ処理**:
     `cond["is_fallback"]` は `list[bool]` で、`cond["hidden"]` と同インデックスに対応する。
     `h_bar = H.mean(axis=0)` の計算時に `is_fallback[i] == True` の試行を除外する。
     ただし `early_stop` ラベルは `summary.json` 由来（`cond["early_stop"]`）であり、
     `hidden` リストのインデックスと `early_stop` リストのインデックスがずれる可能性に注意
     → `hidden` の件数と `early_stop` の件数は必ずしも一致しない（npz 存在 ≠ summary.json の行）。
     グループ化では `early_stop` の長さを境界とし、インデックス範囲内のみ使用する。

  3. **`model_slug` の推定**:
     仕様書では `Path(args.dir).name` だが、`--dir` が複数の場合は最初の dir の名前を使う。
     実際のパス構造: `results/hanoi/full_sweep/<slug>/N{N}_T{tag}/` → `Path(args.dir[0]).name` が slug。

  4. **aggregate 図の T 軸**:
     `--ts` で指定されたすべての T を走査し、有効なデータがあった条件だけプロットする。
     エラーバーは `std(q_vals)` で計算（n_pairs が 1 の場合は std=0、表示はする）。

  5. **統計テーブルの n_pairs**:
     `n_trials < 2` のグループは n_pairs="-" として表示しスキップ。
     `n_pairs = n_trials * (n_trials - 1) // 2`。

  6. **x 軸範囲**:
     仕様書本文と Section 4.4 に矛盾あり（`[0.4, 1.05]` vs `[0.5, 1.0]`）。
     実データの分布が 0.7–0.9 付近に集中（物理的制約 2.5 参照）するため、
     `[0.4, 1.05]` を採用（より広い範囲で外れ値も捕捉できる）。

  7. **KDE + histogram の重ね描き**:
     `scipy.stats.gaussian_kde` で KDE を計算し、半透明のヒストグラムと重ねて描画する。
     KDE のバンド幅はデフォルト（Scott's rule）を使用。
     n_pairs が小さい（< 5）場合は KDE が不安定になるため、ヒストグラムのみ描画する。

### 9.4 Q3 暫定判断

- `stagnation_after_move` は **SG 寄りの補助シグナル**として扱うのが現時点の暫定判断。
- ただし出現頻度が低く、P(q) 分布としての証拠は弱い。
- 後続の P(q) ベース分類では、主判定には使わず、`stagnation_after_move` は
  early_stop 補助特徴または `transitional/undetermined` 判定の参考情報として扱う。
- PM の主シグナルは引き続き `no_move_catchall` と `move_ceiling`。
