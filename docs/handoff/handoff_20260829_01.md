## 8. anchor先行研究の整理

ロードマップが文献由来の実験案を分離している文書:

```text
docs/research_state/literature_extension_branches_20260728.md
```

関連文献:

- Thought Anchors: Which LLM Reasoning Steps Matter?
  - https://arxiv.org/html/2506.19143
- Hidden Markov Modeling of Reasoning Dynamics in Large Language Models
  - https://openreview.net/forum?id=fr9t7r43am
- Dissecting Failure Dynamics in Large Language Model Reasoning
  - https://aclanthology.org/2026.acl-long.401/
- A Statistical Physics of Language Model Reasoning
  - https://arxiv.org/html/2506.04374

区別すべきanchor:

1. Thought anchor
   - その文をcounterfactualに置換すると後続推論・最終回答分布が大きく変わる意味segment。
   - plan、uncertainty management、backtrackingが代表。最初の文やfinal文とは限らない。
2. Failure Dynamicsのanchor
   - 最初のinvalid segment直前にある最後のvalid segment。そこからの再sampleでrecoverabilityを測るcheckpoint。
3. Dataset specのanchor state
   - Pancake state shellから選んだ代表initial stateであり、thought anchorとは無関係。

中心的な理解:

- 早期のsetup/plan/phase分岐は後続軌道の確率を強く偏らせ得る。
- ただし結果を決定論的に固定するとは限らない。Failure Dynamicsでは同じ最後のvalid prefixから20%以上が正答へ回復した。
- dynamicsとしてはanchor/eventを、UMAP上の固定点よりlatent regimeまたはdrift fieldを切り替える離散eventとして扱うのが自然。
- final黒線自体はanchor候補として遅すぎる。探索分離の起点はpre-finalのplan、simulation、verification、backtracking、first distance increase、loop onsetなどから探す。

現在のoutcomeは二段階で扱う。

```text
P(searchでgoalへ到達)
P(finalが正しい | searchでgoalへ到達)
```

- `search_fail`: 探索段階のplan/anchor failure候補。
- `search_success_final_fail`: 探索成功後のselection/final-commit failure。
- `success_final`: 探索とcommitの両方が成功。
- `length_censored`: 右側打ち切り。

## 9. 次セッションのone goal

```text
現在の8 matched trialについて、generated completionを手動phase labelingし、
char span → token span → layer 48 hidden rowの対応表を検証済みで作る。
```

### Must

- phase label仕様を固定する。
  - `setup`
  - `plan`
  - `state_simulation`
  - `move_proposal`
  - `verification`
  - `backtracking`
  - `self_correction`
  - `loop_like`
  - `final_commit`
- 最初は8 trialを手動ラベルし、rule-based候補は補助に留める。
- 各segmentをhalf-open char span `[char_start, char_end)`で保存する。
- `generated_token_ids.npy`を8 trialについて軽量追加取得する。現在のtext cacheには未取得。
- 同じtokenizerでgenerated textをretokenizeし、保存token IDsとの完全一致を検証する。
- 各phaseをhalf-open token span `[a,b)`へ写し、phase後状態を原則`hidden[b]`へ対応させる。
- `b == generated_token_count`ではphase後rowが保存されていないことを明示する。

### Can

- phase終端ごとにcommon PCA-n90座標、boundary jump norm、前後drift、puzzle eventを付ける。
- `first plan end`、`first backtracking end`、`first distance increase`、`loop onset`をcandidate checkpointとして一覧化する。
- 既存8 trialで観察的に、どのcheckpoint以降でsuccess/failure差が見え始めるかpilotする。

### Don't

- phase label仕様とtoken-hidden同期が固まる前にcontinuation生成へ進まない。
- 8 trial確認前に600 trialの自然言語自動分類器を作らない。
- UMAP距離で分離を主張しない。
- final黒線をthought anchorやattractorと断定しない。
- entropy/logit capture、SLDS、activation steeringへ広げない。

### End condition

```text
8 trialについて、目視確認可能なphase annotation表と、
各phaseのchar span・token span・after-phase hidden rowが保存され、
candidate checkpointを決定的に列挙できる。
```

## 10. continuation実験の将来設計

phase同期が完了した後に二種類を分けて行う。

### Recoverability

同じphase終端prefixから複数continuationをsampleし、その時点でsuccess/failureの両方へ分岐できるか測る。

### Anchor intervention

anchor候補segment直前のprefixを固定し、original segment保持条件とresampled/replaced segment条件から複数continuationを生成する。

主要評価:

- `ΔP(search_goal_reached)`
- `ΔP(final_correct | search_goal_reached)`
- common PCA-n90でのbetween-condition separationとwithin-condition variability
- drift方向、phase occupancy、first distance increase、loop onset、goal first-passageの差

phase最終token自体をanchorと呼ばず、phase終端を決定的checkpointとして使う。介入効果が大きく、held-out initial stateでも再現するphase segmentを最終的にanchorと認定する。
