## 4. 未解決の論点・注意

- `debug_prompt.py` は hidden capture なし。hidden trajectory 本番は `run_local.py` を使う。
- `run_local.py` の hidden capture は token mode / relative / all に対応済みだが、Pancake での実GPU smoke test はまだ。
- `<final>` が出ない場合は `moves_final=[]` で `final_accuracy=0`。これは設計上の意図。
- `moves_all_mentions` は探索中・検算中・例示中の `Flip k` をすべて含む。accuracy には使わない。
- `goal_reached_all_mentions=True` かつ `final_accuracy=0` は重要な failure mode。
- N=4 success が集まりにくい場合は、temperature だけでなく `--initial-state` 固定で難度調整する。
- full hidden は容量が重い。最初から全 trial で保存しない。pilot だけ。
- `CLAUDE.md` には「コードは原則 user が手書き」とあるが、今回のセッションでは user 指示により doc 作成・必要実装を進めた。次回も明示指示が無ければ、実装は確認しながら進める。
- git worktree は既に未追跡・変更ファイルが多い。不要に revert しない。
